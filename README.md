## 项目简介

一个轻量级的32位x86操作系统内核，实现了从磁盘启动内核、物理内存管理、页式虚拟内存管理、内核线程和用户进程管理、键盘和显示驱动、简单的文件系统等功能，剔除Makefile等配置文件，核心代码约6000多行，其中C代码5400多行，汇编代码600多行。

**为什么要造这个轮子？**

在本科学习操作系统课程时，老师对着PPT照本宣科，实验也只是学着使用系统调用来实现一点简单点功能，虽然硬着头皮看了当时的教材（汤晓丹）和《现代操作系统》，并且考研时408也复习过一遍，虽然知道了各种调度算法的耗时计算、虚拟地址到物理地址的转换过程，但仍然没有那种直观的感觉，因此后来我又自己学习了MIT的6.1810（https://github.com/Jiangmmh/MIT-6.1810-OS），通过阅读xv6的源码和做课程的lab，对操作系统各部分功能的实现有了更深入的理解。但是xv6是一个已经比较完整的内核，lab只需要看xv6中的主干部分的代码，然后在其上进行修改即可。但对于"操作系统是如何从硬盘启动？操作系统如何与CPU协作，哪些部分由操作系统实现？哪些部分又由CPU实现？" ，为了解决这个疑惑，我决定从头开始实现一个简单的内核，并且要基于x86 CPU（因为xv6是基于riscv的），这个内核主要参考了《操作系统真相还原》的内容。

**结语**

在这个项目上花了很多的时间，从一开始就要去写汇编程序mbr.S和loader.S，来从硬盘中加载内核，包括后面时不时又要使用内联汇编在C程序中执行汇编指令，一开始看不太懂汇编指令和内联汇编的语法，非常难受，因此快速看了王爽的《汇编语言》和李忠的《x86汇编-从实模式到保护模式》，才算入了点门。再就是设置中断控制器（PIC）、定时器（timer），为键盘编写驱动时，要去查看硬件的文档，找到所需要的端口（硬件中的接口寄存器），通过IO指令in和out来与硬件进行通信，这个过程也是非常的繁琐。此外，x86为了实现后向兼容，其设计也是非常繁琐，远不如riscv那般简洁。不过通过从零开始实现这个内核我真正理解了操作系统是如何与CPU进行协作来实现对硬件进行抽象，并为上层应用提供服务的。例如在虚拟内存管理中，操作系统负责构造页表，并将页表的地址存入控制寄存器cr3中；而CPU在开启保护模式和启动分页后（设置cr0寄存器中的控制位），由MMU自动根据cr3中指向的页表来将虚拟地址转化为物理地址并进行访存。例如中断的实现，操作系统为各种可能的中断构造好中断描述符（中断），并统一放入中断描述符表（IDT）中，并将IDT的地址通过`lidt`指令告知CPU；CPU负责在收到中断后，根据中断号从中断描述符表中索引到对应的中断描述符，然后去执行其中指定的中断处理函数（0x80中断为系统调用）。深入地理解了进程和线程不同，其实Linux中根本就没有进程这个概念，所有的执行流都是都是线程，其控制数据结构都是task_struct，只不过有的线程在创建时希望共享父进程的地址空间（代码和数据）、打开文件等资源，其通过tgid来标识共享相同地址空间的线程。因此在操作系统视角上，根本没有线程和进程的区别，其都是一个个的执行流，操作系统对这些执行流进行创建、销毁和调度。相比线程，“进程”创建和销毁的开销大的原因是要重新分配/释放独立的地址空间、加载代码和数据等，调度的开销在于需要更新保存页表的寄存器cr3，可能导致TLB失效、缓存失效等问题。纸上得来终觉浅，绝知此事要躬行。操作系统，或者任何大型系统中都充满了大量的Trade off，有舍有得，很多问题永远不可能存在完美的解决方案，更多的是根据需要来权衡分析，找到较优解，人生又何尝不是呢？
